How I Work

Over the years I have collected a set of engineering principles. I keep them as machine-checkable style guides, so human and AI contributors follow the same rulebook.

Architecture

  • Every piece of code has one home, named by its role: model, repository, service, controller, view.
  • The domain imports no framework, network or file library. Everything outside the process is a port with an adapter around it. Imports point inward.
  • Everything is wired in one composition root, with no service locator and no global state.

Code Hygiene

  • The linter and formatter are the law.
  • Dependencies are pinned and owned: a committed lockfile, no branch dependencies, no latest tags.
  • Configuration is read in one place.
  • Errors are named, carry context and are never swallowed.

Documentation

  • Public APIs are 100% documented, enforced by CI gates (RDoc, Go doc, TypeDoc).
  • No narrating comments in function bodies. The "why" lives in the commit message, and so does the reason for any deliberate deviation from a guide.

Security

  • Secrets are never printed, logged or committed.
  • Single sign-on everywhere (Authentik).
  • Third-party data is untrusted until validated.

Delivery

  • CI runs the tests, and a green pipeline is not the same as a running app: containers are checked after every deploy.
  • Zero-downtime blue/green releases with backward-compatible migrations.

User-facing Text

  • Everything goes through i18n, with English as the base and Hungarian as the first translation.

Working with AI Agents

  • Coding rules live in a Claude Code plugin as style guides with automatic checks.
  • Hooks enforce them on every edit, so the same rulebook applies to every contributor.
